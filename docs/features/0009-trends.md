# 0009 — Trends (design 4f, production Native direction)

## Restatement

The Trends tab stops being a dimmed stub. It shows three segmented views —
Weight, Energy, Consistency — every number computed from REAL user data
(weigh-ins, log entries, targets). No fabricated series, ever: a view without
enough data shows an honest empty state that tells the user exactly what to
log to earn the chart.

## Data truth table (what is real, what we must NOT show)

| Design element | Backing data | Decision |
|---|---|---|
| Weight dots + trend line | `weigh_ins` (schema v1, unused until now) | Build weigh-in logging (this spec) |
| "trend weight today" + Δ since start | derived from weigh-ins | Real; hidden until ≥1 weigh-in |
| "−0.4 kg/week" tile | least-squares slope of trend series | Real; needs ≥2 weigh-ins ≥7 days apart, else "—" |
| "2,545 kcal burn/day" tile | NOT KNOWABLE (no wearable) | REPLACED with "avg eaten kcal/day" — honest |
| "92% days logged" tile | entries days ÷ days since start | Real |
| Protein days hit, by week | entries protein vs target, 8 ISO weeks | Real; empty state under 1 logged day |
| Energy view (design has none beyond tiles) | daily kcal vs target, last 14 days | Bar chart + target line, from entries |

## UI mapping (side-by-side against out/design-trends.png)

- Large title "Trends"; segmented control Weight · Energy · Consistency.
- Card 1: hero number + unit + caption; delta right-aligned (green when the
  direction serves the user's goal, red otherwise — lose wants ↓, gain wants ↑).
- Chart: raw dots in tertiary gray (recessive), 2px smoothed line in tint
  blue, endpoint dot enlarged; hairline gridlines; x labels start/mid/today.
- Tile row: three stat tiles (value + caption), real numbers only.
- Card 2 (Consistency): 8 bars, sequential green ramp by value (validated
  monotonic), 4px rounded tops, ≤24px wide, caption line under.
- TabBar: Trends active (index 1), Report stays dimmed-soon.
- Weight view has "+ Log weight" (the ONLY way data enters weigh_ins v1);
  sheet with decimal input, saves to store → syncs (client upsert per day —
  server PK (user_id, day) makes replays idempotent).

## Dataviz skill compliance (validator run 2026-08-01)

Token set {blue, green, orange, gray} FAILS as a categorical set (orange↔green
protan ΔE 5.1). Therefore: no chart uses two categorical hues. Weight = blue
line + gray de-emphasis dots (shape+role distinct). Energy = green bars +
gray hairline target line (shape distinct, labeled "target"). Protein weeks =
single-hue sequential green ramp — steps generated by surface-mix, asserted
monotonic in a unit test. Marks: 2px lines, r=4 dots with 2px surface ring,
bars ≤24px with 4px rounded data-end, hairline solid gridlines, all text in
text tokens. Contrast WARN discharged via direct labels (hero, endpoint,
tile values) — never color-alone.

## Domain math (pure, unit-tested)

- `smoothWeights(points, window=7)`: centered moving average over available
  neighbors (no fabricated padding).
- `weeklySlopeKgPerWeek(points)`: least-squares over day numbers; null when
  span < 7 days or < 2 points.
- `dailyKcal(entries, lastNDays, today)`: buckets by local day string.
- `proteinDaysByWeek(entries, target, weeks=8, today)`: ISO-week buckets of
  days where protein ≥ target.
- `loggedPercent(entryDays, startDay, today)`.

## Out of scope (logged, not half-built)

- Energy "burn" estimation (needs wearable / adaptive TDEE — Phase 3).
- Report tab (stays honest-soon).
- Weigh-in edit/delete UI (v1 = re-log same day overwrites; server PK
  guarantees one row per day).
